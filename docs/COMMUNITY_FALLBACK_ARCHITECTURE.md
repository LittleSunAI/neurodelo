# Архитектура форума и общения

## Цель

Дать интерфейсу полнофункциональные локальные сценарии общения, не привязывая компоненты к конкретной базе, WebSocket-серверу или сервису перевода.

## Слои

1. Компоненты `ForumView` и `MessagesView` работают только через `usePlatform()`.
2. `PlatformProvider` изменяет единое состояние `PlatformState.community`.
3. `communityGateway` создаёт темы, ответы, сообщения, жалобы и перевод.
4. `NEXT_PUBLIC_USE_COMMUNITY_FALLBACKS` выбирает локальный или API-режим.
5. API-режим обращается только к `/api/v1/community/*`.

## Данные

`CommunityState` содержит:

- категории форума;
- темы;
- сообщения тем;
- участников чатов;
- разговоры;
- сообщения;
- жалобы;
- состояние автоматического перевода;
- последний открытый разговор.

## Безопасность

- fallback не хранит пароли и внешние токены;
- пользователь может блокировать собеседника;
- жалобы не удаляют содержимое автоматически;
- настоящий перевод должен вызываться только через сервер;
- API-заглушка возвращает 503 до настройки backend;
- вложения позднее должны проходить антивирусную проверку и выдаваться по временным ссылкам.

## Замена fallback

Установить:

```env
NEXT_PUBLIC_USE_COMMUNITY_FALLBACKS=false
```

И реализовать серверные маршруты:

- `POST /api/v1/community/forum/threads`;
- `POST /api/v1/community/forum/threads/:id/posts`;
- `POST /api/v1/community/conversations/:id/messages`;
- `POST /api/v1/community/translate`;
- `POST /api/v1/community/reports`.

Интерфейс и типы при этом менять не требуется.
