# Финальный аудит репозитория NEURODELO

> Этот отчёт описывает исходный архив до подготовки публикации. Apache-2.0 и результаты последующей сборки и тестов зафиксированы в [CHECK_REPORT.md](../CHECK_REPORT.md); исходные выводы ниже сохранены для истории.

**Дата:** 19 октября 2026 года.  
**Проверяемый материал:** подготовленная очищенная версия локального прототипа NEURODELO 0.23.0 для публикации исходного кода на GitHub.  
**Статус:** **готов как комплект исходников для дальнейшей публикации после выбора лицензии и проверки прав; НЕ является готовым публичным сервером.**

## 1. Итог

Проверены полнота исходного кода, состав исключённых файлов, целостность архива, ссылки документации, относительные подключения исходных модулей, целостность JSON, контрактные и несколько статических проверок, настройка контейнера PostgreSQL и демонстрационные учётные записи.

**Не выявлено подтверждённой потери необходимого кода сайта при очистке архива.** Отдельные материалы самостоятельных игровых проектов намеренно исключены. В архив добавлены канонические документы с описанием целевого шифрования (система ещё не внедрена и не проверена).

**Критические вопросы, которые нельзя назвать закрытыми:**

1. **Не выбрана лицензия.** В репозитории нет `LICENSE`. Перед объявлением проекта свободным необходимо выбрать лицензию и проверить права на код, изображения и материалы участников.
2. **Не доказана полная собираемость и работоспособность приложения.** Установка пакетов в данной изолированной среде не завершилась; типизация, компоновка итоговой сборки и сквозные испытания на этой копии не проведены.
3. **Нельзя развёртывать как публичный многопользовательский сервис.** Действующий локальный файловый механизм хранения нельзя подменять подготовленной схемой PostgreSQL; облачное файловое хранение, полноценное шифрование и внешние службы ещё не интегрированы и не проверены.

## 4. Безопасность — выявленные ограничения

**Высокий приоритет перед публикацией сайта:**

- В `lib/server/local-auth-store.ts` известные демонстрационные пользователи создаются для локальной разработки; в обычном режиме `NODE_ENV=production` они отключены, кроме специально включённого `NEURODELO_TEST_DEMO_USERS=true`. **Не включать этот флаг в публичной среде.**
- В `services/auth-gateway.ts` открыто присутствуют демонстрационные учётные данные для имитационного режима. Это **учебные**, а не найденные реальные секреты; демонстрационный режим нельзя использовать как защиту публичного сайта.
- Файл `.env.example` ориентирован на локальные испытания: `COOKIE_SECURE=false`, локальное файловое хранение, демонстрационные переключатели, незаполненные ключи. Его **нельзя копировать в производственную среду без пересмотра**.
- В `infrastructure/docker-compose.local.yml` установлены явно демонстрационные запасные пароли. База, Redis и MinIO привязаны к локальному адресу; настройки предназначены **только для локальной разработки**.
- Полное шифрование, отдельная служба ключей и восстановление ещё не внедрены и не испытывались. Документация об алгоритме не заменяет реализацию.
- При публикации документов и изображений необходима самостоятельная проверка авторских прав и сведений, которые владелец не хочет раскрывать. Автоматический поиск не гарантирует отсутствие всех возможных конфиденциальных данных.

**Исправления, уже присутствовавшие в очищенном комплекте:**

- Защитное условие для демонстрационного администратора в обычном производственном режиме.
- Правильное подключение тома PostgreSQL 18: `/var/lib/postgresql`.
- Исключение `.env*`, `.data/`, `backups/`, закрытых ключей и сборок через `.gitignore`.

## 6. Что остаётся сделать владельцу перед публикацией исходного кода

1. Выбрать MIT, GPLv3 или другую лицензию, согласовать права и добавить полный текст в `LICENSE`.
2. Самостоятельно просмотреть примеры изображений, исторические отчёты и документы: всё ли разрешено показывать публично.
3. На машине разработчика выполнить `npm ci`, `npm run lint`, `npm run typecheck`, `npm run build` и `npm run test:release`; при наличии необходимых условий отдельно `npm run test:http`.
4. Перед первой отправкой изменений проверить `git status` и `git diff --cached --name-only`; убедиться, что не добавлены `.env`, личные файлы и доступы.
5. Не подключать реальных пользователей, пока не завершены база, шифрование, защита медиа, почта, резервное восстановление и серверные испытания.
