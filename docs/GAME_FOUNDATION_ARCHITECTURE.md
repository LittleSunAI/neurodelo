# Архитектура игровой основы

## Цель

Сейчас нужна не окончательная игра, а стабильный контракт для будущей системы из другого проекта.

Интерфейс знает только о следующих операциях:

- выбрать класс;
- получить текущую прогрессию;
- распределить очко характеристики;
- провести тренировочный бой;
- получить результат и награду;
- показать разблокированную косметику.

## Адаптер

`services/game-gateway.ts` поддерживает два режима:

- `fallback` — простая локальная формула для проверки интерфейса;
- `api` — запросы к `/api/v1/game`.

Будущий движок должен возвращать структуры `HeroProgression` и `BattleResult`. Внутреннюю формулу можно полностью заменить, не переписывая страницы профиля и арены.

## Отделение от квалификации

- `Skill` и профессиональный XP отражают реальные навыки.
- `HeroProgression` отражает игрового персонажа.
- Вклад может дать небольшое количество hero XP.
- Победа в игре не повышает Frontend, Backend, QA и другие профессиональные уровни.
- Проигрыш в игре не снижает репутацию участника.

## Не включено

- PvP в реальном времени;
- ставки;
- покупка силы;
- вывод внутриигровых единиц;
- торговля предметами;
- окончательный баланс классов;
- способности и экипировка со статами.
