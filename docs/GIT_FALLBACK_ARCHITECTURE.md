# Архитектура Git fallback

## Цель

Дать интерфейсу и продуктовой логике единый Git-контракт до подключения настоящего GitHub App. Компоненты не должны знать, используются локальные данные или серверный API.

## Переключение режима

```env
NEXT_PUBLIC_USE_GIT_FALLBACKS=true
```

- `true` — операции выполняет локальный `gitGateway`;
- `false` — gateway обращается к `/api/v1/git`.

## Слои

```text
React UI
  ↓
PlatformProvider
  ↓
gitGateway
  ├─ fallback implementation
  └─ /api/v1/git implementation
```

## Модель данных

`GitIntegrationState` содержит:

- подключённый профиль;
- выбранный репозиторий;
- снимки репозиториев;
- issues;
- Pull Request;
- CI checks;
- commits;
- журнал синхронизации.

Git-состояние хранится вместе с `PlatformState`, поэтому участвует в миграциях, экспорте и сбросе локального профиля.

## Подтверждение вклада

Профессиональный XP начисляется только после следующей цепочки:

```text
внутренняя задача
→ связанный issue
→ Pull Request
→ успешные checks
→ approved
→ merged
→ закрытый issue
→ verified recognition
→ XP + portfolio
```

Кнопка благодарности не может заменить техническое подтверждение вклада.

## Создание проекта

При локальном создании проекта автоматически создаются:

- репозиторий;
- issues из задач;
- базовые коммиты;
- ветки;
- README-снимок.

Редактирование названия репозитория, ветки, README и задач обновляет Git-снимок.

## API-контракт

Подготовленные адреса:

- `POST /api/v1/git/connect`;
- `POST /api/v1/git/disconnect`;
- `POST /api/v1/git/repository/select`;
- `POST /api/v1/git/repositories/:id/sync`;
- `POST /api/v1/git/pull-requests`;
- `POST /api/v1/git/pull-requests/:id/checks`;
- `POST /api/v1/git/pull-requests/:id/merge`.

До подключения GitHub App catch-all route возвращает HTTP 503. Это предотвращает ложное впечатление, что реальная интеграция уже активна.

## Будущая настоящая интеграция

Серверная реализация должна использовать GitHub App, а не пользовательский Personal Access Token в браузере. Нужны:

- серверное хранение private key;
- установка приложения только на выбранные репозитории;
- минимальные permissions;
- проверка webhook signature;
- идемпотентная обработка событий;
- журнал аудита;
- защита от повторного начисления XP;
- ручное подтверждение спорных вкладов.

## Безопасность

- секреты отсутствуют в клиентском bundle;
- fallback не исполняет код репозитория;
- merge работает только внутри локального состояния;
- API-mode без серверной настройки возвращает 503;
- XP можно получить один раз за связанный результат;
- issue закрывается только после состояния `ready` и merge.
