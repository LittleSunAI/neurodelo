# Архитектура изображений героя и fal.ai

## Цель

Изображение героя не должно быть жёстко связано с одним поставщиком. Пользовательский интерфейс обращается только к `heroImageGateway`, а провайдер можно переключить переменной окружения.

## Поток fallback

```text
Hero Studio
  -> heroImageGateway (fallback)
  -> локальные статусы queued/generating/ready
  -> SVG data URL 512x512
  -> PlatformState.heroImages
  -> localStorage v5
```

Fallback:

- не использует интернет;
- не расходует баланс;
- не требует секретов;
- поддерживает отмену;
- возвращает тот же контракт, что и настоящий провайдер.

## Поток fal.ai

```text
Браузер
  -> POST /api/v1/hero-images/generate
  -> сервер проверяет параметры
  -> сервер читает FAL_KEY и FAL_HERO_MODEL_ID
  -> fal.run/<model-id>
  -> единый HeroImageVariant
  -> браузер сохраняет результат
```

Ключ существует только на серверной стороне:

```env
FAL_KEY=...
FAL_HERO_MODEL_ID=...
```

Запрещено:

```env
NEXT_PUBLIC_FAL_KEY=...
```

## Контракты

### HeroImageVariant

Хранит:

- источник;
- статус;
- URL или data URL;
- размеры;
- MIME-тип;
- prompt;
- модель;
- пресет;
- время создания.

### HeroImageGenerationRecord

Хранит:

- провайдера;
- статус;
- prompt;
- модель;
- время начала и завершения;
- результат или ошибку.

### HeroImageLibrary

Хранит:

- основной вариант;
- список вариантов;
- историю генераций;
- счётчики загрузок и генераций;
- локальный лимит вариантов.

## Загруженные изображения

До сохранения браузер:

1. проверяет MIME-тип;
2. проверяет размер до 5 МБ;
3. показывает кадрирование;
4. обрезает изображение в квадрат;
5. уменьшает до 512×512;
6. сохраняет WebP или JPEG.

После backend вместо data URL должен возвращаться постоянный URL объектного хранилища.

## Переключение

Fallback включён:

```env
NEXT_PUBLIC_USE_HERO_IMAGE_FALLBACKS=true
```

Fallback отключён:

```env
NEXT_PUBLIC_USE_HERO_IMAGE_FALLBACKS=false
```

При отключении браузер обращается к нашему `/api/v1/hero-images/generate`, а не напрямую к fal.ai.

## Что подключить позже

- очередь fal.ai для долгих задач;
- webhook с проверкой подписи;
- лимиты генераций на пользователя;
- серверную модерацию prompt и результата;
- S3-совместимое хранилище;
- удаление старых файлов;
- image-to-image режим;
- единый каталог разрешённых моделей;
- учёт стоимости до запуска генерации;
- ручное подтверждение платной операции.
