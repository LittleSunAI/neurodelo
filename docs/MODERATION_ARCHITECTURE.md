# Архитектура модерации и административной панели

## Цель

Модерация вынесена в отдельный заменяемый слой. Интерфейс не обращается напрямую к базе или внешнему сервису. Все операции проходят через `moderationGateway`.

## Слои

```text
AdminView
  ↓
PlatformProvider
  ↓
moderationGateway
  ├─ fallback: локальные решения и задержки
  └─ api: /api/v1/moderation/*
```

## Состояние

`PlatformState.moderation` содержит:

- `cases` — очередь дел;
- `decisions` — решения;
- `appeals` — апелляции;
- `externalLinks` — проверяемые ссылки;
- `featureFlags` — управляемые функции;
- `auditLog` — журнал действий;
- `sanctions` — активные ограничения;
- `activeReviewer` — текущий демонстрационный проверяющий.

## Жизненный цикл дела

```text
queued
→ reviewing
→ action-required
→ resolved / dismissed
→ appealed
→ upheld / overturned / rejected
```

## Принципы

1. Каждое решение содержит причину и автора.
2. Апелляция не удаляет исходное решение.
3. Санкции отделены от жалоб.
4. Feature flags не удаляют код и фиксируются в аудите.
5. ИИ может подготовить сводку, но решение принимает человек.
6. На сервере доступ должен проверяться отдельно от интерфейса.

## API-контракты

Подготовлены пути:

- `POST /api/v1/moderation/cases/assign`;
- `POST /api/v1/moderation/cases/resolve`;
- `POST /api/v1/moderation/appeals`;
- `POST /api/v1/moderation/appeals/review`;
- `POST /api/v1/moderation/links/review`;
- `POST /api/v1/moderation/feature-flags/toggle`.

Пока сервер не подключён, API возвращает HTTP 503 с понятным описанием необходимых переменных.

## Миграция

Схема состояния обновлена с версии 10 на версию 11. Старое состояние получает демонстрационную очередь, ссылки, флаги и журнал без потери профиля, проектов, Git, форума, признания и игры.

## Что потребуется на backend

- отдельная роль администратора и модератора;
- серверная проверка полномочий;
- неизменяемый audit log;
- хранение доказательств;
- сроки санкций;
- уведомления участникам;
- ограничение доступа к персональным данным;
- антивирусная и репутационная проверка ссылок;
- экспорт решений и апелляций;
- политика хранения и удаления данных.
