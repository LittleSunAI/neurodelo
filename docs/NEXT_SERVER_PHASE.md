# Следующая стадия: серверная реализация

Локальные шаги 1–18 завершены. Дальнейшая работа — отдельная server-side фаза.

## Серверный этап 1. Инфраструктура

- Docker Compose для web, API, worker, PostgreSQL, Redis и MinIO;
- окружения development, staging и production;
- секреты и ротация ключей;
- резервное копирование;
- централизованные логи.

## Серверный этап 2. Аккаунты

- настоящая регистрация;
- secure cookies;
- refresh sessions;
- восстановление пароля;
- подтверждение почты;
- 2FA/passkeys;
- rate limiting и антибот-защита.

## Серверный этап 3. PostgreSQL

- запуск миграций на тестовой базе;
- проверка отката;
- проверка всех RLS-политик;
- индексы и планы запросов;
- seed для staging;
- retention и удаление данных.

## Серверный этап 4. Основные API

- реализация OpenAPI-контрактов;
- валидация запросов;
- единый error format;
- audit log;
- idempotency для критических операций;
- интеграционные тесты.

## Серверный этап 5. GitHub App

- минимальные permissions;
- установка только на выбранные repositories;
- webhook signature validation;
- синхронизация issues, PR, CI и commits;
- проверка связи Git-пользователя с профилем;
- безопасное начисление XP.

## Серверный этап 6. Файлы и fal.ai

- S3/MinIO;
- антивирусная проверка;
- signed URLs;
- серверный вызов fal.ai;
- очередь генераций;
- лимиты и модерация изображений.

## Серверный этап 7. Community realtime

- WebSocket;
- сообщения и read receipts;
- уведомления;
- перевод через провайдера;
- moderation pipeline;
- антиспам.

## Серверный этап 8. Тестовый публичный запуск

- staging;
- закрытая альфа;
- сбор обратной связи;
- мониторинг ошибок;
- нагрузочное тестирование;
- юридические документы;
- постепенное включение feature flags.
