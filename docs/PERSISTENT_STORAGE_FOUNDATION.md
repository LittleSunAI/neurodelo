# Persistent Storage Foundation

## Что реализовано

Локальная версия больше не зависит только от памяти процесса.

По умолчанию используется файловый драйвер:

```env
PERSISTENCE_DRIVER=file
NEURODELO_DATA_DIR=.data
NEXT_PUBLIC_USE_DURABLE_LOCAL_STATE=true
```

На диск сохраняются:

- локальные аккаунты и PBKDF2-хеши паролей;
- одноразовые токены восстановления;
- подписанные серверные сессии и их отзыв;
- rate-limit buckets;
- дневная квота и idempotency fal.ai;
- полный PlatformState пользователя;
- журнал событий безопасности;
- история отправки email без сохранения полного адреса получателя;
- локальный стабильный HMAC-secret, если `AUTH_SECRET` не задан.

## Как устроен слой

Все серверные модули обращаются к интерфейсу `PersistentStore`:

- `FilePersistentStore` — текущий локальный драйвер;
- `MemoryPersistentStore` — только тесты и временная разработка;
- будущий `PostgresPersistentStore` сможет реализовать тот же контракт.

Файлы записываются через временный файл и атомарный `rename`. Каталог создаётся с правами `0700`, файлы — `0600` там, где ОС поддерживает POSIX-права.

Повреждённый JSON не сбрасывается молча: он переименовывается в `.corrupt-*`, а сервер сообщает об ошибке.

## Ограничения

Файловый драйвер рассчитан на один локальный Node.js процесс. Он не заменяет PostgreSQL и Redis для:

- нескольких серверных экземпляров;
- горизонтального масштабирования;
- транзакций между несколькими сущностями;
- высокой частоты записи;
- распределённых блокировок и очередей.

На Vercel и других эфемерных/serverless файловых системах этот режим использовать нельзя.
