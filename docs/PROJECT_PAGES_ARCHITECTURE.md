# Архитектура публичных страниц и редактора проектов

## Цель

Шаг 10 создаёт локальную модель open-source проекта, которая работает без сервера, но использует контракты, пригодные для последующей замены на API и базу данных.

## Главная модель

`OpenSourceProject` содержит:

- идентификатор и slug;
- владельца;
- статус и стадию;
- описание;
- репозиторий, ветку и лицензию;
- стек, теги и требуемые специализации;
- roadmap;
- роли;
- задачи;
- новости;
- релизы;
- FAQ;
- документы;
- правила XP;
- статистику участников и подписчиков.

## Поток данных

```text
UI проекта
  ↓
PlatformProvider
  ↓
platformGateway
  ↓
localStorage fallback
```

После появления backend нижний слой заменяется запросами `/api/v1/projects`, а компоненты и модели остаются прежними.

## Создание проекта

```text
CreateProjectWizard
  ↓
createProject(project)
  ↓
PlatformProvider обновляет state.projects
  ↓
platformGateway сохраняет состояние
  ↓
проект доступен в каталоге, редакторе и /p/<slug>
```

## Публичный маршрут

`app/p/[slug]/page.tsx` поднимает `PlatformProvider` и передаёт slug в `PublicProjectPage`.

Страница:

- находит проект по slug;
- учитывает статус публикации;
- показывает публичные вкладки;
- позволяет подписаться и вступить;
- для владельца открывает редактор.

## Редактор

`ProjectEditorView` работает с копией выбранного проекта. Изменения сохраняются явно через `updateProject`, поэтому пользователь может редактировать форму до нажатия кнопки сохранения.

Отдельные операции provider:

- `createProject`;
- `updateProject`;
- `addProjectTask`;
- `addProjectNews`;
- `addProjectRoadmapItem`;
- `selectProject`;
- `toggleProjectSubscription`.

## Миграция

Состояние версии 5 могло не содержать проектов. При загрузке:

1. читается старое состояние;
2. устанавливается версия 6;
3. добавляются демонстрационные проекты;
4. выбирается `open-companion`;
5. создаётся пустой список подписок;
6. результат записывается под новый ключ.

## Будущая Git-интеграция

В шаге 11 к проекту будет подключён `GitProvider`. Он сможет заполнять:

- README;
- issues;
- Pull Request;
- статусы CI;
- коммиты;
- участников;
- подтверждённые вклады.

Локальный project fallback при этом останется тестовым провайдером.

## Безопасность будущей реализации

- пользователь не должен передавать Git-токен браузерному localStorage;
- реальное подключение следует делать через GitHub App/OAuth на сервере;
- разрешения выдаются только выбранным репозиториям;
- webhook должен проверяться по подписи;
- редактор обязан проверять права владельца на API и в базе, а не только в интерфейсе;
- HTML из README и документов нужно очищать перед отображением.
