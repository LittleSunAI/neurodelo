# Безопасное локальное файловое хранилище

## Назначение

Локальный object-storage закрывает разработческий сценарий до подключения MinIO/S3. Он предназначен для одного Node.js-процесса и не является заменой production-хранилища.

## Что реализовано

- серверные маршруты `/api/v1/files`;
- обязательная подписанная сессия;
- same-origin проверка изменяющих запросов;
- лимит 5 загрузок в минуту и 20 в сутки по умолчанию;
- глобальный предел тела запроса;
- проверка magic bytes, а не доверие расширению или MIME браузера;
- разрешены PNG, JPEG, WebP, PDF и безопасный UTF-8 текст;
- лимиты разрешения и общего числа пикселей изображения;
- безопасное имя файла и случайное имя физического объекта;
- SHA-256 и дедупликация одного файла у одного владельца;
- карантин, одобрение и отклонение;
- проверка владельца при чтении и удалении;
- отдельное разрешение модератора для review;
- скачивание только одобренных объектов;
- `Content-Disposition: attachment` и изолирующий CSP при скачивании;
- автоматическая очистка старых карантинных и отклонённых файлов.

## Каталоги

```text
.data/objects/quarantined/
.data/objects/approved/
.data/objects/rejected/
```

Метаданные хранятся в namespace `stored-files` через общий `PersistentStore`.

## Ограничения

- нет антивируса;
- JPEG пока не перекодируется и может сохранять EXIF;
- PDF проверяется по сигнатуре, но не проходит sandbox-анализ;
- multipart body до разбора должен дополнительно ограничиваться reverse proxy;
- файловый драйвер не поддерживает несколько серверов;
- для production требуется MinIO/S3, quarantine bucket, scanner worker и signed URLs.
